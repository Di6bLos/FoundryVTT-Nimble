# Animation Config Validation Guide

## What Was Implemented

A multi-layer prevention system to catch animation config errors before they reach production:

### 1. **JSON Schema Validation**
   - **File**: `scripts/schemas/animation-config.schema.json`
   - **Purpose**: Defines the required structure for melee animation entries
   - **Key Rule**: Every melee entry MUST have a `meleeSwitch` field

### 2. **Validation Script**
   - **File**: `scripts/validateAnimations.mjs`
   - **Purpose**: Enforces the schema with helpful error messages
   - **Entry Point**: `npm run validate:animations`

### 3. **Pre-Commit Hook**
   - **Config**: `lefthook.yml`
   - **Trigger**: Automatically runs when `public/auto-animations/fvtt-global-animations.json` is staged
   - **Behavior**: Blocks commit with clear error message if validation fails

## How It Works

### ✅ Valid Entry (Good)
```json
{
  "id": "88e7609a-4557-4d5f-983c-99f91332061f",
  "label": "Dagger",
  "menu": "melee",
  "meleeSwitch": {                    // ✓ REQUIRED
    "video": { ... },
    "sound": { ... }
  },
  "primary": { ... }
}
```

### ❌ Invalid Entry (Bad)
```json
{
  "id": "88e7609a-4557-4d5f-983c-99f91332061f",
  "label": "Snowblind",
  "menu": "melee",
  // ✗ MISSING meleeSwitch - VALIDATION FAILS
  "primary": { ... }
}
```

### Error Output Example
```
❌ Animation Config Validation Failed: public/auto-animations/fvtt-global-animations.json

  #/definitions/meleeEntry/required:
    Melee entry at index 3 is missing required field "meleeSwitch"
    Label: "Snowblind"
    ID: 88e7609a-4557-4d5f-983c-99f91332061f
    This field is required for all melee entries to prevent MeleeSwitch.svelte crashes.

📋 How to fix:
   Add meleeSwitch object to all melee animation entries.
   Example: "meleeSwitch": { "video": {...}, "sound": {...} }
```

## When Validation Runs

### Automatic (Pre-Commit)
When you stage the animation config file:
```bash
git add public/auto-animations/fvtt-global-animations.json
git commit -m "Update animations"
# ↓ Validation runs automatically
# If it fails: commit is blocked, you see the error, fix it, and try again
```

### Manual
```bash
npm run validate:animations
# or with a custom file:
npm run validate:animations /path/to/animations.json
```

---

## Why This Matters

The original bug occurred because:
1. Three spells were added to the melee category
2. They were missing the `meleeSwitch` field
3. MeleeSwitch.svelte tried to read undefined → silent error
4. Component didn't render when expanded → UI appeared broken

**With this validation:**
- The error is caught during development, not in production
- Error message is clear and actionable
- Developers can't accidentally commit bad animation configs
